About

The path to what I do now has run through several very different kinds of work — barista work, calculus mentoring, jewelry making, custom fabrication of shipping crates for stained-glass windows — and, eventually, code. After years away from university, I recently returned to complete the upper-division math I needed to finish my B.S. with a minor in physics. Along the way I discovered that what I enjoy most is creative problem solving — particularly designing and building things.

Most of what I build starts with a problem — one I've run into myself, or one someone tells me about. Building with AI suits that approach well: it's a great tool for brainstorming ideas, assisting in designing something, and having it built — and it turns out to supply interesting new problems of its own.

These days I build AI tooling — processes and skills that make working with AI more reliable and more inspectable, by moving as much of the work as possible into things that can actually be verified.

Projects

The three projects below are one line of reasoning: each exists because of what the previous one surfaced.

latent-world-engine in development
problem
AI can generate game content, but generated content is hard to trust — and a game is too complex to verify as a whole.
approach
Decompose games into atomic components simple enough that correctness of form can be checked, then build upward from verified pieces, keeping AI generation inside structures the framework can validate.
status
In active development; not yet public. Its core heuristics seeded both tools below.

└─ which led to

project-spec-interrogator in use
problem
AI output can't fit a need that was never articulated — and users often haven't fully worked out their own needs, even to themselves.
approach
A Claude Code skill that runs a structured interrogation dialog: it pushes back on vague language, treats contradictions as leads rather than errors, and continues until the spec is concrete enough to build against.
status
In use. It produced the architectural spec for process-exhumer-tool, and specialized derivatives of it are built into both of the other projects here.

└─ which led to

process-exhumer-tool built — first run pending
problem
Models are biased toward jumping to an answer, so even a clearly specified process isn't reliably followed — and that can't be prompted away.
approach
Change the goal: instead of asking AI to do the thing, have it build code that does the thing. A five-stage pipeline refines a task into a contract, recursively decomposes it, generates and verifies code for each piece, and assembles a standalone program — with any remaining AI judgment confined to a single, countable seam.
status
All five stages built. The first end-to-end run is the current milestone.
